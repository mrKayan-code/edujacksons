# 0003 — Модель безопасности аутентификации: TLS в транзите, bcrypt в покое

- **Статус:** принято
- **Дата:** 2026-07-07
- **Контекст:** реализован модуль `auth` (Фаза 0): регистрация/логин присылают пароль,
  сервер выдаёт JWT. Возник вопрос: как защитить пароль от перехвата (man-in-the-middle),
  и не безопаснее ли хешировать пароль на клиенте.

## Проблема

Две **разные** угрозы, которые легко спутать и попытаться закрыть одним средством:

1. **В транзите** — перехват канала (MITM, прослушка сети). JSON-тело запроса приложением
   не шифруется — по проводу это открытый текст.
2. **В покое** — утечка/дамп БД. Если хранить пароль как есть, при утечке компрометируются
   все аккаунты.

Соблазн «хешировать пароль на фронтенде» **не решает** угрозу №1: перехваченный хеш
становится паролем-эквивалентом, и злоумышленник повторяет его напрямую в обход клиента
(атака **pass-the-hash**). А угрозу №2 клиентский хеш тоже не закрывает — сервер всё равно
обязан хешировать полученное значение своим алгоритмом/солью.

## Решение

Каждую угрозу закрываем на своём уровне:

| Угроза | Уровень | Средство |
|---|---|---|
| В транзите (MITM) | транспорт | **TLS (HTTPS)** |
| В покое (утечка БД) | приложение/БД | **серверный bcrypt** (хеш + соль на пользователя) |

Конкретно:

- **Пароль передаётся «сырым» по HTTPS**, хешируется **на сервере** через `BCryptPasswordEncoder`
  перед сохранением; в БД лежит только `password_hash`. Клиентского хеширования нет.
- **Аутентификация stateless на JWT**: пароль уходит по сети только на `/register` и `/login`;
  далее клиент носит подписанный токен, а не пароль. Секрет JWT — только из окружения.
- **Пароль нигде не логируется**; базовая проверка силы — `@Size(min = 8)` на входном DTO.

### Требование к продовому деплою (обязательное)

- На проде (домашний Arch-сервер, отдельная фаза) весь внешний трафик — **только по HTTPS**.
- TLS терминирует **реверс-прокси** (Caddy или nginx) с сертификатом Let's Encrypt, стоящий
  перед приложением. Включить **HSTS**. HTTP → редирект на HTTPS.
- Локально (`http://localhost`) TLS не нужен — трафик не покидает машину.

### Явно вне скоупа сейчас

- Протоколы, где сервер вообще не видит пароль (**SRP**, **OPAQUE**/PAKE) — защищают даже от
  скомпрометированного сервера, но сложны и для MVP оверинжиниринг. Знаем, что существуют.
- Refresh-токены, ротация ключей, 2FA — возможные расширения после MVP.

## Последствия

- Деплой-фаза получает жёсткое требование: без HTTPS в прод не выходим (иначе пароли и JWT
  идут открытым текстом).
- Реализация ядра остаётся простой и стандартной (TLS + bcrypt + JWT) — меньше своего
  security-кода = меньше ошибок.
