# ADR 0001 — Технологический стек и архитектурный подход

- **Дата:** 2026-07-04
- **Статус:** принято

## Контекст
Личная платформа репетитора по программированию + подготовка к ЕГЭ. Две цели: рабочий
продукт к учебному году и прокачка промышленного Java-стека / микросервисов (карьерная цель).

## Решения

### Java 21 + Spring Boot 3.x
Актуальный LTS и индустриальный стандарт. Максимальная польза для резюме и найма.

### Gradle (Kotlin DSL) — не Maven
Современнее, чаще в новых вакансиях, типобезопасные скрипты сборки.
Бонус: касание синтаксиса Kotlin (пригодится, если позже будет мобилка на Kotlin).

### Модульный монолит → микросервисы позже
Микросервисы для одного репетитора — оверинжиниринг на старте. Но выучить распил нужно.
Компромисс: сначала работающий монолит с чёткими границами модулей, затем осознанный вынос
`judge-service` (естественно изолирован, ресурсоёмок) как учебное упражнение.

### Judge0 для исполнения кода — не свой sandbox
Свой безопасный sandbox (cgroups/seccomp/no-network) — отдельный опасный проект.
Judge0 даёт изоляцию из коробки. Прячем за интерфейсом `CodeExecutor`, чтобы позже
заменить своим движком как учебную фазу.

### Kafka с Фазы 2 — не RabbitMQ
Kafka встречается в целевых вакансиях. Используем реально (`submissions → judge`),
а не «для галочки»; она же станет шиной между микросервисами при выносе judge.

### PostgreSQL + Flyway, Redis, Spring Security + JWT
Стандартный проверенный набор. UUID-ключи — упрощают будущий распил на сервисы.

### Frontend: Next.js + TypeScript (отдельный SPA)
API-first: бэк отдаёт чистый REST/JSON, фронт — один из клиентов. Легко прицепить мобилку.

## Последствия
- Больше инфраструктуры на старте (Kafka, Judge0, Redis в Docker Compose) — принимаем ради обучения.
- Дисциплина границ модулей обязательна, иначе распил на сервисы станет болью.
