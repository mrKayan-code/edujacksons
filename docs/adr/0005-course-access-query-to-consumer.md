# 0005 — CourseAccessQuery живёт у потребителя (courses), а не у провайдера

- **Статус:** принято
- **Дата:** 2026-07-10
- **Уточняет:** ADR `0004` (пункт 1 «только публичные интерфейсы + view-записи между модулями»).

## Контекст

ADR `0004` разместил межмодульные интерфейсы у модуля-**провайдера** (кто владеет данными):
`courses.CourseDirectory` и `groups.CourseAccessQuery`. Тонкие бины-адаптеры сделали граф
**бинов** ацикличным, и Spring стартует без `allow-circular-references`. Но на уровне **пакетов**
зависимость осталась двусторонней:

- `courses.CourseService` импортировал `groups.service.CourseAccessQuery` → `courses → groups`
- `groups.GroupService` импортирует `courses.service.CourseDirectory` → `groups → courses`

Цикл пакетов `courses ↔ groups` не мешает запуску, но противоречит цели проекта — модульный
монолит, готовый к распилу на микросервисы. При выносе модуля в сервис двусторонняя связь
пакетов означает двусторонний рефакторинг.

## Решение

Ключевое наблюдение: у `courses` и `groups` потребность в данных **двусторонняя**, поэтому
правило «интерфейс у провайдера» (ADR `0004`) и симметричное ему «интерфейс у потребителя» —
оба дают цикл. Ацикличный граф получается, только если **оба** порта живут в одном модуле.

Выбран `courses` (он ниже в графе — зависит лишь от `auth`):
- `CourseAccessQuery` — порт, объявленный потребителем `courses`, реализован в `groups`.
- `CourseDirectory` — порт, реализованный в `courses`, вызывается из `groups`.

Итог — все стрелки идут **`groups → courses`**, граф пакетов ацикличен (DAG):

```
groups ──► courses ──► auth
  (импортирует CourseDirectory + CourseAccessQuery из courses.service;
   реализует CourseAccessQuery; courses на groups не ссылается вовсе)
```

Принцип адаптеров-листьев из ADR `0004` сохраняется без изменений: `CourseAccessQueryImpl`
и `CourseDirectoryImpl` зависят только от своих репозиториев.

## Последствия

- (+) Граф пакетов, а не только бинов, стал ацикличным. `courses` можно вынести в сервис,
  не трогая `groups` на уровне зависимостей пакетов.
- (+) Код совпал с тем, как границу уже описывали README модулей.
- (−) Конвенция «интерфейс у провайдера» из ADR `0004` больше не универсальна: для
  двусторонних пар побеждает «оба порта у одного модуля». Это осознанное отступление ради DAG.
- Правило на будущее: если модули A и B нуждаются друг в друге, порты обоих направлений
  размещаем в одном из них (том, что ниже в графе зависимостей), а не по владельцу данных.
