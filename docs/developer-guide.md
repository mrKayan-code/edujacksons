# Гайд разработчика EduJacksons

Добро пожаловать в команду разработки EduJacksons! Этот документ поможет вам быстро сориентироваться в проекте, понять архитектурные принципы и начать писать код, который соответствует стандартам системы.

## 🌟 О проекте
EduJacksons — это платформа для репетитора по программированию. 
**Главная архитектурная цель**: создать модульный монолит, который в будущем может быть легко разделен на микросервисы. Поэтому мы очень строго следим за границами модулей.

## 🏗 Архитектура

### Модульный монолит
Приложение разделено на функциональные модули (`auth`, `courses`, `groups` и т.д.). 
**Золотое правило**: Модули не должны иметь тесных связей. 

- **Запрещено**: Прямое обращение к репозиторию другого модуля.
- **Разрешено**: Вызов публичного сервиса другого модуля.
- **Рекомендуется**: Использование интерфейсов-границ (Query/Directory), чтобы избежать циклических зависимостей (см. пример в модуле `groups` $\to$ `CourseAccessQuery`).

### Слоеная архитектура (внутри модуля)
Каждый модуль разбит на 4 слоя. Зависимости всегда идут только сверху вниз:

`API (Controller/DTO)` $\to$ `Service` $\to$ `Repository` $\to$ `Domain (Entity)`

1. **API**: Обрабатывает HTTP, валидирует входящие данные через `@Valid`, мапит сущности в DTO. Не содержит бизнес-логики.
2. **Service**: «Сердце» модуля. Здесь живет вся бизнес-логика и управление транзакциями (`@Transactional`).
3. **Repository**: Тонкий слой доступа к БД через Spring Data JPA.
4. **Domain**: Чистые данные (Entities, Enums). Не зависят ни от чего.

## 🛠 Технологический стек
- **Язык**: Java 21 (LTS).
- **Фреймворк**: Spring Boot 3.x.
- **Сборка**: Gradle (Kotlin DSL).
- **БД**: PostgreSQL.
- **Миграции**: Flyway (никакого `ddl-auto=update`, только SQL-скрипты).
- **Безопасность**: Spring Security + JWT (stateless).
- **Тесты**: JUnit 5 + Testcontainers (для интеграционных тестов с реальной БД/Kafka).

## 🚀 Жизненный цикл фичи (Step-by-Step)

Если вам нужно добавить новый функционал, следуйте этому алгоритму:

1. **Синхронизация с ТЗ**: Проверьте `task.md`. Если функционала там нет или он описан неточно — сначала обновите ТЗ.
2. **Архитектурное решение**: Если фича меняет структуру данных или связи между модулями, создайте новый ADR в `docs/adr/NNNN-slug.md`.
3. **Схема БД**: Создайте новую миграцию Flyway в `src/main/resources/db/migration/V__...sql`.
4. **Слой Domain**: Создайте Entity и необходимые Repository.
5. **Слой Service**: Реализуйте бизнес-логику. Не забудьте про `@Transactional`.
6. **Слой API**: Создайте DTO (используйте `record`) и добавьте методы в Controller.
7. **Тестирование**: Напишите Unit-тесты для сервиса и интеграционный тест (с Testcontainers) для проверки всего пути от API до БД.
8. **Документация**: Обновите `api-contracts.md` и README вашего модуля.

## 📝 Стандарты кодинга

- **Неизменяемость**: Используйте `record` для DTO и любых контейнеров данных.
- **Безопасность**: Все записи в БД должны быть защищены проверкой владения (`ownerId`). Никогда не доверяйте `id`, пришедшему из запроса, без проверки прав.
- **Обработка ошибок**: Не используйте try-catch для управления потоком. Бросайте доменные исключения (наследуемые от `ApiException`), которые будут превращены в HTTP-ответы в `GlobalExceptionHandler`.
- **UUID**: В качестве первичных ключей всегда используйте `UUID`.
- **Логирование**: Используйте SLF4J. Не выводите чувствительные данные (пароли, токены) в логи.

## 📦 Запуск проекта
1. Поднимите инфраструктуру: `docker-compose up -d`.
2. Запустите приложение через IDE или `./gradlew bootRun`.
3. Health-check доступен по адресу: `/actuator/health`.
