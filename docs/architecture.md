# Архитектура

> Детализируется по мере фаз. Верхнеуровневое решение — модульный монолит с границами,
> готовыми к выносу в микросервисы. См. `task.md` §5.

## Стиль
- **Модульный монолит** на Spring Boot. Каждый модуль — свой пакет с чёткой публичной
  границей (сервисный интерфейс), внутренности не торчат наружу.
- Модули общаются через интерфейсы/события, а не лезут в чужие таблицы напрямую —
  это то, что позволит вынести модуль в отдельный сервис без переписывания половины кода.

## Слои внутри модуля (пакетная структура)
```
<module>/
  api/        REST-контроллеры, DTO
  domain/     сущности, доменная логика
  repository/ Spring Data JPA
  service/    прикладная логика, публичный интерфейс модуля
  config/     конфигурация модуля
```

## Асинхронность
- `submissions → judge` через **Kafka** (топик заявок на проверку, топик результатов).
- Это заранее «микросервисный» контракт: при выносе `judge-service` меняется только
  транспорт/деплой, не логика.

## Целевая эволюция
1. Монолит (MVP).
2. `judge-service` — первый вынос (Kafka-шина).
3. При необходимости — `ege-service`, `notifications-service`.
