# ЕГЭ / КЕГЭ — интеграция и проверка

> Самая рискованная по контенту часть. Ключевая идея — изоляция источника за абстракцией,
> чтобы платформа не зависела от хрупкого скрапинга.

## Абстракция ContentSource
```
interface ContentSource {
    List<EgeTask> fetchTasks(criteria);   // задания
    // + метаданные варианта
}
```
Реализации:
- **ManualImport** — свой JSON-банк заданий. Основной путь на старте, стабильный.
- **KompegeScraper** — парсинг внешних банков (kompege.ru и т.п.).
  - ⚠️ Юридически серо, технически хрупко (ломается при редизайне, риск бана по IP).
  - Агрессивное кэширование результатов в свою БД.
  - Никакой жёсткой рантайм-зависимости: если источник недоступен — работаем на кэше/своём банке.
- **OwnBank** — собственные авторские задания.

## Автопроверка ответов (типы заданий 1–27)
- Большинство заданий КЕГЭ — короткий ответ (число/строка/последовательность) → сверка строк
  с нормализацией (пробелы, порядок для множеств и т.п.).
- Задания с программированием (17, 25, 27) — могут уходить в общий Judge-пайплайн.
- Формат ответа хранится в `ege_tasks.answer_format`; проверялка выбирается по типу.

## Этапность
- MVP (Фаза 4): `ManualImport` + автосверка коротких ответов, несколько заданий.
- После MVP: `KompegeScraper`, покрытие большего числа типов, генерация вариантов.

## Открытые вопросы
- Точная модель типов заданий и правил сверки.
- Легальность источников — уточнить, что можно использовать.
