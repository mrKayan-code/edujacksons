# Модуль Authentication (`auth`)

Модуль отвечает за управление пользователями, аутентификацию и авторизацию в системе. 
Реализован по принципу **stateless-аутентификации** с использованием JWT (JSON Web Tokens).

## 🎯 Назначение
- Регистрация новых пользователей.
- Аутентификация (логин) по email и паролю.
- Выпуск и валидация JWT-токенов.
- Управление ролями (`TEACHER`, `STUDENT`).
- Обеспечение безопасности эндпоинтов через Spring Security.

## 🏗 Архитектура модуля

Модуль разделен на слои в соответствии с общим стандартом проекта:
- `api/`: Контроллеры и DTO. Точка входа для HTTP-запросов.
- `service/`: Бизнес-логика. `AuthService` является единственным публичным интерфейсом модуля.
- `repository/`: Доступ к данным через Spring Data JPA.
- `domain/`: Сущности (`User`, `Role`).
- `config/`: Настройка Spring Security, JWT-фильтры и свойства.

### Ключевые компоненты

| Компонент | Ответственность |
|---|---|
| `AuthService` | Регистрация, логин, получение данных текущего пользователя. |
| `JwtService` | Генерация токенов (HS256) и их парсинг/валидация. |
| `JwtAuthenticationFilter` | Перехватывает каждый запрос, извлекает JWT и устанавливает личность пользователя в `SecurityContext`. |
| `SecurityConfig` | Описывает цепочку фильтров: какие пути открыты (`permitAll`), а какие требуют аутентификации. |

## 🔐 Модель безопасности

Проект следует индустриальным стандартам защиты данных (подробнее в `docs/adr/0003-auth-security.md`):

1. **В транзите (MITM)**: Пароли и токены передаются в открытом виде внутри TLS-туннеля. **HTTPS обязателен** для всех продовых окружений.
2. **В покое (БД)**: Пароли никогда не хранятся в открытом виде. Используется одностороннее хеширование **bcrypt** с солью.
3. **Stateless**: Сервер не хранит сессии. Личность пользователя подтверждается подписью JWT.

## 🔄 Основные потоки (Flows)

### 1. Регистрация (`POST /api/auth/register`)
`Request DTO` $\to$ `Валидация` $\to$ `Проверка уникальности email` $\to$ `bcrypt(password)` $\to$ `Save User` $\to$ `Issue JWT` $\to$ `Response`

### 2. Логин (`POST /api/auth/login`)
`Request DTO` $\to$ `AuthenticationManager` (сверка хеша пароля в БД) $\to$ `Issue JWT` $\to$ `Response`

### 3. Защищенный запрос (напр. `GET /api/auth/me`)
`HTTP Header (Bearer <token>)` $\to$ `JwtAuthenticationFilter` $\to$ `JwtService.parse()` $\to$ `SecurityContextHolder (Set Authentication)` $\to$ `Controller`

## 🚀 API Эндпоинты

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| `POST` | `/api/auth/register` | Public | Создание аккаунта и выдача токена |
| `POST` | `/api/auth/login` | Public | Проверка пароля и выдача токена |
| `GET` | `/api/auth/me` | Authenticated | Получение данных профиля текущего пользователя |

## 🛠 Разработка и тестирование
- **Смена секрета JWT**: Настраивается через переменную окружения `JWT_SECRET` или в `application.yml`.
- **Тестирование**: Основные тесты логики JWT находятся в `src/test/java/dev/edujacksons/auth/service/JwtServiceTest.java`.
