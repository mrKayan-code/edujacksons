# Модуль Judge (`judge`)

Модуль отвечает за физическое исполнение кода учеников в изолированной среде и возвращение результатов выполнения.

## 🎯 Назначение
- Исполнение исходного кода на заданном языке программирования.
- Ограничение ресурсов (время выполнения, память) для предотвращения DoS-атак.
- Возврат стандартного вывода (stdout), ошибок (stderr) и статуса завершения процесса.
- Интеграция с внешним API Judge0.

## 🏗 Архитектура модуля

Модуль спроектирован как максимально независимый компонент, который может быть вынесен в отдельный микросервис без изменения бизнес-логики других модулей.

- `api/`: Контракты запросов и ответов (`JudgeRequest`, `JudgeResult`), которые используются как схемы сообщений в Kafka.
- `config/`: Настройки подключения к Judge0.
- `service/`: Логика исполнения и интеграция с транспортным слоем.

### Ключевые компоненты

| Компонент | Ответственность |
|---|---|
| `CodeExecutor` | Интерфейс-адаптер для исполнения кода. Позволяет сменить бэкенд исполнения (напр. с Judge0 на свой sandbox) без правки кода сервисов. |
| `Judge0CodeExecutor` | Реализация `CodeExecutor`, использующая HTTP API Judge0. |
| `JudgeService` | Оркестратор: принимает запрос, вызывает исполнителя, нормализует вывод и выставляет итоговый вердикт по тестам. |
| `JudgeRequestListener` | Kafka-потребитель, который слушает топик `judge.requests` и запускает процесс проверки. |

## ⚙️ Процесс проверки (Execution Flow)

1. **Триггер**: `JudgeRequestListener` получает `JudgeRequest` из Kafka.
2. **Исполнение**: Для каждого теста в запросе `JudgeService` вызывает `CodeExecutor.execute()`.
3. **Изоляция**: `Judge0CodeExecutor` отправляет код и входные данные в Judge0. Judge0 исполняет код в изолированном контейнере.
4. **Результат**: Получается `ExecutionResult` (stdout, статус: OK/TLE/RE/CE).
5. **Сверка**: `JudgeService` сравнивает полученный stdout с ожидаемым (игнорируя лишние пробелы/переносы строк).
6. **Вердикт**: Формируется `Verdict` (ACCEPTED, WRONG_ANSWER и т.д.).
7. **Ответ**: Итоговый `JudgeResult` с вердиктами по всем тестам отправляется в топик `judge.results`.

## 🛡 Безопасность и изоляция
- **Sandbox**: Исполнение кода происходит **вне основного приложения**. Даже если ученик напишет `System.exit(0)` или бесконечный цикл, это затронет только временный контейнер Judge0, а не бэкенд платформы.
- **Лимиты**: Для каждого запуска задаются жесткие лимиты по времени и памяти.
- **Stateless**: Модуль не хранит состояние. Все данные для проверки приходят внутри сообщения Kafka.

## 🚀 Интеграция
- **Транспорт**: Apache Kafka.
- **Внешний сервис**: Judge0 (Self-hosted).
- **Языки**: На текущем этапе поддерживается Python (language_id=71), что оптимально для подготовки к ЕГЭ.
