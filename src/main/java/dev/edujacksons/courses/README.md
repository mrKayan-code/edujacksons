# Модуль Courses (`courses`)

Модуль отвечает за создание образовательного контента: курсов и связанных с ними учебных материалов.

## 🎯 Назначение
- Создание, редактирование и удаление курсов преподавателем.
- Управление материалами курса (лекции, инструкции).
- Организация последовательности материалов (порядок отображения).
- Контроль доступа к курсам (владелец vs ученик).

## 🏗 Архитектура модуля

Модуль следует стандартному многослойному подходу:
- `api/`: Контроллеры (`CourseController`) и DTO для управления курсами и материалами.
- `service/`: Бизнес-логика. `CourseService` управляет жизненным циклом курсов и материалами.
- `repository/`: Доступ к таблицам `courses` и `materials` через JPA.
- `domain/`: Сущности `Course` и `Material`, а также `MaterialType`.

### Ключевые компоненты

| Компонент | Ответственность |
|---|---|
| `CourseService` | Основная логика: управление правами доступа, CRUD курсов и материалов, расчет индекса порядка. |
| `CourseAccessQuery` | Интерфейс для проверки доступа пользователя к курсу (реализуется в модуле `groups` для предотвращения циклических зависимостей). |
| `MaterialType` | Определение типа контента (на текущий момент поддерживается только `LECTURE`). |

## 🔐 Модель доступа и владения

В модуле реализована строгая модель прав:

1. **Владение (Ownership)**: Каждый курс имеет владельца (`ownerId`). Только владелец-преподаватель имеет право изменять или удалять курс и его материалы.
2. **Доступ на чтение (Read Access)**:
   - Владелец всегда имеет доступ на чтение.
   - Ученик имеет доступ на чтение, если он привязан к группе, которой назначен данный курс (проверяется через `CourseAccessQuery`).
3. **Изоляция**: Если пользователь не является владельцем и не имеет доступа через группу, система возвращает 403 Forbidden или 404 Not Found.

## 📚 Материалы и LECTURE формат

Материалы привязаны к курсу и имеют `orderIndex` для сортировки.
На текущем этапе поддерживается тип **`LECTURE`**:
- Контент хранится в текстовом поле (`body`).
- Используется формат Markdown.
- Слайды внутри одной лекции разделяются тройным тире (`---`).

## 🚀 API Эндпоинты

### Курсы
| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| `POST` | `/api/courses` | Teacher | Создание нового курса |
| `GET` | `/api/courses` | Auth | Список доступных курсов (свои + через группы) |
| `GET` | `/api/courses/{id}` | Owner/Student | Детали курса |
| `PATCH` | `/api/courses/{id}` | Owner | Обновление данных курса |
| `DELETE` | `/api/courses/{id}` | Owner | Удаление курса |

### Материалы
| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| `POST` | `/api/courses/{id}/materials` | Owner | Добавление материала в курс |
| `GET` | `/api/courses/{id}/materials` | Owner/Student | Список материалов курса по порядку |
| `GET` | `/api/courses/{id}/materials/{mid}` | Owner/Student | Контент конкретного материала |
| `PATCH` | `/api/courses/{id}/materials/{mid}` | Owner | Редактирование материала |
| `DELETE` | `/api/courses/{id}/materials/{mid}` | Owner | Удаление материала |

## 🛠 Особенности реализации
- **Предотвращение циклов**: Чтобы избежать циклической зависимости между `courses` $\to$ `groups` $\to$ `courses`, модуль `courses` определяет интерфейс `CourseAccessQuery`, который реализуется внутри модуля `groups`.
- **Авто-индексация**: При добавлении материала без указания `orderIndex`, система автоматически назначает ему следующий порядковый номер.
