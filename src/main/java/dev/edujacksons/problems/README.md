# Модуль Problems (`problems`)

Модуль отвечает за управление банком задач по программированию и наборами тестов для их автоматической проверки.

## 🎯 Назначение
- Создание, редактирование и удаление задач преподавателем.
- Управление наборами тестовых случаев (входные данные $\to$ ожидаемый вывод).
- Обеспечение доступа к задачам только для тех учеников, которые имеют доступ к курсу, к которому привязана задача.
- Предоставление спецификаций исполнения (язык, лимиты) для модуля `judge`.

## 🏗 Архитектура модуля

Модуль следует стандартному многослойному подходу:
- `api/`: Контроллеры (`ProblemController`) и DTO.
- `service/`: Бизнес-логика. `ProblemService` — главный API модуля.
- `repository/`: Доступ к таблицам `problems` и `test_cases` через JPA.
- `domain/`: Сущности `Problem` и `TestCase`.

### Ключевые компоненты

| Компонент | Ответственность |
|---|---|
| `ProblemService` | CRUD задач и тестов, проверка прав доступа через `CourseAccessQuery`. |
| `ProblemExecutionSpec` | Контейнер с параметрами исполнения (язык, лимиты времени/памяти), который передается в конвейер проверки. |
| `ProblemDirectory` | Интерфейс для доступа к данным задачи из других модулей (например, из `submissions`). |

## 🧪 Система тестирования (Test Cases)

Каждая задача имеет набор тестовых случаев (`TestCase`). 
- **Структура теста**: Входные данные (`input`) $\to$ Ожидаемый вывод (`expected_output`).
- **Принцип проверки**: Вывод программы ученика сравнивается с ожидаемым. Лишние пробелы в конце строк и переводы строк в конце вывода игнорируются.
- **Агрегация вердикта**: Если хотя бы один тест провален, общим вердиктом задачи становится вердикт первого непройденного теста.

## 🚀 API Эндпоинты

| Метод | Путь | Доступ | Описание |
|---|---|---|---|
| `POST` | `/api/problems` | Teacher | Создание новой задачи |
| `GET` | `/api/problems/{id}` | Owner/Student | Получение условий задачи (без ожидаемых ответов тестов!) |
| `PATCH` | `/api/problems/{id}` | Owner | Редактирование задачи |
| `DELETE` | `/api/problems/{id}` | Owner | Удаление задачи |
| `POST` | `/api/problems/{id}/tests` | Owner | Добавление тестового случая |
| `DELETE` | `/api/problems/{id}/tests/{tid}` | Owner | Удаление теста |

## 🛠 Особенности реализации
- **Безопасность**: Эндпоинты возвращают данные задачи только если пользователь является владельцем или учеником, имеющим доступ к связанному курсу.
- **Разделение данных**: В API никогда не возвращаются `expected_output` тестов, чтобы избежать их копирования учениками.
