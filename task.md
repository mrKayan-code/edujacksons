# EduJacksons — платформа для репетиторства по программированию

> Мастер-ТЗ и источник правды. Правится инкрементально. Детали крупных тем — в `docs/`.
> Дата старта планирования: 2026-07-04. Цель запуска MVP: к началу учебного года (~сентябрь 2026).

---

## 1. Видение

Личная платформа репетитора по программированию и подготовке к ЕГЭ (информатика).
Учитель (владелец) готовит курсы, лекции и задания; ученики решают задачи по
программированию с автопроверкой, отправляют решения, изучают материалы и готовятся к
ЕГЭ/КЕГЭ. Платформа заодно — «полигон» для прокачки промышленного Java-стека и
микросервисной архитектуры (карьерная цель владельца — Java-разработчик).

### Две цели проекта (держать в балансе)
1. **Продукт** — рабочая платформа к учебному году для реальных учеников.
2. **Обучение** — современный Java-стек, микросервисы, инфраструктура «как в индустрии».

Принцип: **сначала работающий продукт (модульный монолит), потом осознанный распил на
микросервисы как учебное упражнение** — не «микросервисы ради галочки».

---

## 2. Роли и пользователи

- **TEACHER** (владелец) — создаёт курсы, задачи, варианты, проверяет решения, ведёт учеников.
- **STUDENT** — записан в группы/курсы, решает задачи, отправляет решения, смотрит материалы, готовится к ЕГЭ.
- *(на будущее)* ADMIN — если появятся другие репетиторы.

---

## 3. Скоуп MVP («всё сразу минимально» — тонкий вертикальный срез)

К учебному году должен работать сквозной сценарий:

1. Учитель регистрируется, создаёт курс и группу, добавляет ученика.
2. В курсе есть материал (лекция) и задача по программированию с тестами.
3. Ученик логинится, читает материал, пишет код в редакторе, отправляет решение.
4. Решение асинхронно проверяется (Judge0) → ученик видит результат по тестам.
5. Задание с ручной проверкой: ученик присылает решение → учитель ставит оценку/фидбэк.
6. ЕГЭ (тонко): вручную импортировано несколько заданий/вариант, автосверка ответов.

Всё, что шире этого сценария, — в разделе «Роадмап (после MVP)».

### Явно вне MVP (Non-goals)
- Свой sandbox исполнения кода (берём Judge0).
- Полноценный парсер КЕГЭ по всем типам заданий 1–27.
- Оплаты/биллинг, мобильное приложение, мультитенантность (много репетиторов).
- Kubernetes, полноценный observability-стек (Prometheus/Grafana) — учебные фазы позже.

## 4. Технологический стек (зафиксировано)

### Backend (ядро)
- **Java 21** (LTS)
- **Spring Boot 3.x** (Web, Data JPA, Security, Validation, Actuator)
- **Gradle (Kotlin DSL)** — сборка
- **PostgreSQL** — основная БД; **Flyway** — миграции
- **Redis** — кэш, сессии, rate-limit
- **Spring Security + JWT** — аутентификация/авторизация (роли TEACHER/STUDENT)
- **Apache Kafka** — асинхронный канал `submissions → judge`; в будущем — шина между микросервисами
- **JUnit 5 + Testcontainers** — тесты с реальными PostgreSQL/Kafka в Docker

### Judge (проверка кода)
- **Judge0** (self-hosted) за интерфейсом `CodeExecutor`.
- Свой sandbox — учебная фаза позже (изоляция: cgroups/seccomp/no-network).

### Frontend
- **Next.js + TypeScript**, **TanStack Query**, **Monaco Editor**, **Tailwind CSS**.
- Общение с бэком по REST/JSON (**API-first** — фронт лишь один из клиентов).

### Инфраструктура
- **Docker Compose** — локальный и продовый стек (self-hosted, домашний сервер на Arch — отдельная сессия).
- **GitHub Actions** — CI (сборка, тесты).
- Prometheus/Grafana, Kubernetes — учебные фазы позже.

> Обоснования решений — в `docs/adr/`.

## 5. Архитектура: модульный монолит → микросервисы

Один Spring Boot проект с чёткими модулями (границы готовы к выносу в сервисы).
Подробнее — `docs/architecture.md`.

### Модули
| Модуль | Ответственность |
|---|---|
| `auth` | Пользователи, роли, регистрация, JWT |
| `courses` | Курсы, лекции, материалы, уроки |
| `problems` | Банк задач по кодингу + наборы тестов |
| `submissions` | Приём решений, статусы, история |
| `judge` | Проверка кода через Judge0 (→ **микросервис №1** позже) |
| `ege` | Варианты, `ContentSource` (парсер КЕГЭ + ручной импорт), автосверка ответов |
| `grading` | Ручная проверка учителем, оценки, фидбэк |
| `groups` | Ученики, группы, назначение заданий, дедлайны, прогресс |
| `notifications` | Уведомления (результат проверки, дедлайны) |

### План перехода к микросервисам (учебная цель)
1. Собрать и задеплоить **модульный монолит** (MVP).
2. Вынести **`judge-service`** первым — он естественно изолирован и ресурсоёмок,
   общается через Kafka. Это даёт честный опыт распила монолита.
3. Далее по необходимости/интересу — `ege-service`, `notifications-service`.

## 6. ЕГЭ / КЕГЭ

Абстракция **`ContentSource`** с реализациями:
- `KompegeScraper` — парсинг внешних банков (kompege.ru и т.п.). **Хрупко и юридически серо** —
  агрессивно кэшируем, не делаем жёсткой зависимости, изолируем за интерфейсом.
- `ManualImport` — свой JSON-банк заданий (основной путь на старте).
- `OwnBank` — собственные задания.

Автосверка ответов по типам заданий ЕГЭ 1–27 — отдельная фаза после MVP.
Подробнее — `docs/ege-integration.md`.

## 7. Роадмап

Правило работы: **одна рабочая сессия = одна фаза**. Не тащим весь проект в контекст.
Чеклисты обновляем по мере выполнения (`[ ]` → `[x]`).

### Фаза 0 — Скелет (3–5 дней)
- [x] Инициализация Gradle-проекта (Kotlin DSL), структура модулей
- [x] Docker Compose: PostgreSQL, Redis, Kafka
- [x] Flyway + базовая схема БД
- [x] `auth`: регистрация/логин, JWT, роли TEACHER/STUDENT
- [x] Actuator health-check, GitHub Actions CI (build + test)

### Фаза 1 — Курсы и ученики
- [x] `courses`: CRUD курсов, лекций, материалов (материал=LECTURE: markdown-слайды через `---`)
- [x] `groups`: группы, запись учеников по email, назначение (привязка курса к группе)
- [x] Учитель создаёт курс, добавляет ученика, ученик видит материал (сквозной тест на Testcontainers)
- [x] Границы модулей через публичные интерфейсы + view-записи (ADR `0004`)

### Фаза 2 — Задачи по кодингу + автопроверка (бэкенд ✅)
- [x] `problems`: задачи + наборы тестов (открытые/скрытые), доступ = доступ к курсу задачи
- [x] `submissions`: приём решения, статусы (QUEUED → FINISHED/FAILED), история
- [x] `judge`: исполнение за `CodeExecutor` (Judge0 HTTP-клиент; fake в тестах), сверка вывода + вердикт
- [x] Kafka: асинхронная проверка `submissions → judge → submissions` (самодостаточное событие, ADR `0006`)
- [x] Сквозной тест на Testcontainers (реальные PostgreSQL + Kafka): отправка → асинхронный вердикт
- [ ] **Фронт (отдельная сессия):** скаффолд Next.js+TS, Monaco-редактор, отправка, результат по тестам
      — вынесено из бэкенд-сессии (другой стек с нуля; карьерная цель владельца — Java-бэкенд).

### Фаза 3 — Ручная проверка
- [ ] `grading`: воркфлоу проверки, оценки, фидбэк учителя
- [ ] Ученик видит статус и комментарии

### Фаза 4 — ЕГЭ (тонко)
- [ ] `ege`: модель варианта/задания, `ContentSource` + `ManualImport`
- [ ] Импорт нескольких заданий, автосверка ответов
- [ ] Экран прохождения варианта

### Фаза 5+ — После MVP (учебное/расширение)
- [ ] Вынос `judge-service` в отдельный микросервис (Kafka-шина)
- [ ] Парсер КЕГЭ (`KompegeScraper`), больше типов заданий ЕГЭ
- [ ] `notifications`, дедлайны, прогресс-дэшборды
- [ ] Свой sandbox исполнения кода
- [ ] Observability (Prometheus/Grafana), деплой на домашний Arch-сервер, k8s
- [ ] Мобильный клиент (Kotlin/Compose или React Native)

## 9. Открытые вопросы (решить позже)
- Деплой на домашний Arch-сервер (отдельная сессия). **Требование:** внешний трафик только
  по HTTPS — TLS терминирует реверс-прокси (Caddy/nginx) + Let's Encrypt. См. ADR `0003`.
- Дизайн/UX фронта (пока функциональный минимум).
- Точная модель типов заданий ЕГЭ для автопроверки.

### Решённые вопросы
- **Модель безопасности auth** (2026-07-07). Пароль передаётся сырым по HTTPS и хешируется
  на сервере (bcrypt); клиентского хеширования нет (не спасает от MITM — pass-the-hash).
  Транзит защищает TLS, базу — bcrypt. Прод обязательно за HTTPS. Детали — ADR `0003`.
- **Язык задач в Judge0 на старте — только Python** (2026-07-04). Ученики готовятся к
  ЕГЭ/КЕГЭ, где Python оптимален: нетребователен к статической типизации, минимум кода
  для результата. Навык низкоуровневой разработки (C++) — задача университета, не наша;
  на старте не распыляемся. Другие языки — возможное расширение после MVP.
